# AI Creator OS · 个人编辑工作台产品与技术方案

2026-11-19 · 方案修订 0.2 · 第一条交付线为单人、本机编辑。产品设计和工程实测分别记录，真实平台权限需要使用相应账号验证。

## 1. 第一篇文章如何完成

作者看到两条关于同一项 AI 功能的消息，一条来自发布者，另一条来自解释这项功能的中文作者。两条都值得保留，因为一条说明发布者承诺了什么，另一条提出了使用条件。作者再补一句自己的观察，并关联一次能够说明条件的经历。工作台据此形成一个读者问题。作者确认母稿之后，同一判断可以写成 X 上的一段讨论、公众号里一个讲清因果的案例，以及小红书上一组可收藏的图卡。

**成功条件**是作者愿意署名，能指认文中自己贡献的判断，并能把关键事实还原到原始材料。首轮试用同时记录实际改稿耗时、改动类型和理由。采集数量与生成字数仅供观察。

## 2. 输入及采集

| 来源 | 入口和保存内容 | 边界与异常 |
|---|---|---|
| X 指定账号 | 用户名、帖子 ID、时间、文本和原帖地址。手动触发单账号最近窗口读取 | 需要账号 API 凭证。首版每次取最近 10 条原创帖或回复，重复取回按帖子 ID 合并。窗口之外的历史材料用链接补录 |
| X、公众号及其他原文 | 粘贴链接，选留标题、作者、原文节选和事件名；公众号公开文章可先预读后保存 | 读取失败仍可保存链接，等作者补节选。只有标题的材料在形成母稿前会提示补充 |
| 本人观点与案例 | 在看素材时写一句自己愿意署名的判断。案例单独保存适用条件与可核对的经过 | 只将作者主动确认为本人的材料用作第一人称依据；公开报道保留原作者归属 |
| 历史文章 | 选择文风样本，提供具有代表性的段落 | 只用于学习叙述方式。涉及立场时由作者另选当前观点 |

运营时可从发布者、一线使用者、中文解释者各选少数高价值账号。候选名单由作者维护。排序先看来源与本人经验的关联，再看材料能否核实。完整追踪的后续版本需保存分页游标、覆盖时段和缺口，账号实际费用及读取授权纳入接入验收。

## 3. 素材、事件与选题

**重复链接**以规范化地址识别，X 的帖子按 ID 对齐，重复读取保留原有节选。**同一事件**允许多条独立材料同时存在。首版对近似标题做轻量归组，作者可以合并或拆开事件。页面上的数量表示素材条数。后续再增加「发布方／实测／转述」的来源关系和首发时间核验，生成事件摘要与观点分歧。

候选选题从外部标题和事件名寻找有词语重合的本人观点，显示匹配到的原话供作者判断。候选标题、外部材料和本人观点可以一次带进新稿。没有匹配时，记录作者对这个问题的回应后再建稿。首版的关联依据是文本匹配，跨语言语义匹配待积累人工选题样本后再评估。

## 4. 编辑界面与版本流转

| 页面 | 主要操作 | 结果 |
|---|---|---|
| 素材台 | 搜索、按类型筛选、查看原文、归组、从候选话题发起选题 | 可在多篇文章复用同一条来源或个人材料 |
| 写作台 | 左侧选择外部依据，中间写母稿，右侧选择个人观点、案例及文风样本。可先整理素材，也可以调用模型 | 保存正文、选用的素材 ID、改稿理由和版本。查看历史，可将旧稿恢复为新版本 |
| 平台稿 | 左侧编辑选定渠道，右侧对照已确认的母稿 | 分别保存标题、正文和图卡。同一平台可以多次编辑 |
| 文风规则 | 查看实际改稿理由，提炼候选写作偏好。选择独立文章记录评测 | 人工通过后加入后续母稿生成，可拒绝或撤回 |

初稿包含来源标记。查看标记对应的节选和链接后，编辑者逐段核对事实、引语、案例归属和论证边界。未保存的修改在离开编辑区时提示。素材集合发生变化后需要按新材料保存并重新确认。母稿修订或历史恢复后，旧平台稿仍可阅读；导出时须先核对并保存至新母稿版本。

## 5. 一篇母稿如何变成三个作品

| 平台 | 编辑目标 | 已实现的文件交付 | 发布前由作者核对 |
|---|---|---|---|
| X | 首帖独立可读，一条放不下时把上下文、证据或例外拆成后续帖 | TXT，按空行组织短帖。标题与正文可编辑 | 每条是否成立、长短是否适合目标账号、来源和链接是否可用 |
| 公众号 | 从场景引出读者问题，展开证据、作者判断、限制与实践启示 | UTF-8 HTML，提供标题及段落，可在浏览器打开后复制到编辑器 | 排版、摘要、封面及真实后台粘贴效果 |
| 小红书 | 封面提出一个明确问题，中间逐页举例，最后给出可操作的做法 | ZIP，包含配文、图卡可编辑文字及 1080 × 1440 PNG。第一张使用封面样式 | 手机阅读字号、文字换行、图序和配文一致性 |

例题可用「怎样判断 Agent 写出的代码值得保留？」。X 可用一条真实的审查问题引发讨论，公众号可围绕一个实际变更展开，小红书可逐页解释同一段代码的修改理由。真实案例由作者提供，测试夹具独立标识。公众号草稿箱、X Articles、知识星球可沿用适配器思路开发；首版交付文件，不依赖写入账号权限。真实同步阶段应区分导出成功、远端写入成功和状态未知，按远端回执核对并防重复。

## 6. 写作、核对与文风学习

- 模型输入按用途标明选题、外部节选、本人原话、案例和文风样本。只有用户主动点选时才提交给其配置的服务。正式规则限已启用项。
- 模型返回结构化稿件。母稿接受前校验引用是否合法、是否引用本人观点、选用外部材料时是否留下外部依据。这个检查只能定位引用，无法证明段落受来源支持。界面保留原材料供用户判断。
- 作者审稿时核对四件事。读者得到的具体答案是什么？哪句话是我的判断？哪项事实需要查原文？结论适用于哪些情形？
- 渠道生成以已确认母稿为输入，单独设置首帖、公众号论证和图卡密度要求。作者审核缩写、标题和图卡是否扩大了原文结论。
- 保存改稿时可归类为事实、观点、结构、措辞。填写理由时记录从本次开始编辑到保存的时长，含期间停留，仅作近似指标。候选规则记录来源文章和理由。作者用另一篇确认稿检验，然后接受、拒绝或撤回。
- 后续质量评测增加同一留出样本的盲评 A/B、原稿与改稿差异以及失败样本。首版的人工反馈流与 Phase 0 自进化模拟实验分别验收。

## 7. 技术实现与数据边界

单人版本采用 Python 本地 HTTP 服务、原生浏览器界面、Canvas 导出和 SQLite。这样可把注意力放在真实写作体验，并在正式决定 Hermes 和 Autoloop 是否接入前验证编辑功能。Windows 提供双击入口。启动说明见仓库首页。

| 实体 | 关键字段与关联 | 何时变化 |
|---|---|---|
| 素材 | 稳定 ID、类型、作者、标题、链接、节选、事件和日期 | 空链接可补入节选，已保存节选保留；事件分组可更正 |
| 选题与母稿 | 问题、所选素材、依据版本、各次修订、作者确认的修订 ID | 改稿新增修订；历史恢复写入新版本 |
| 渠道稿 | 渠道、母稿修订 ID、标题、正文、图卡及历史副本 | 保存前确认母稿；导出时校验来源修订 |
| 文风规则 | 来源文章、人工理由、候选状态、独立评测文章和结论 | 审批后参与母稿生成；撤回保留记录 |
| 工作区 | 整数版本、上述业务数据的序列化内容 | SQLite 单次事务提交；并发编辑比较版本，发现冲突拒绝覆盖 |

单用户小规模素材使用单行快照简化本机安装和恢复。随着素材量、历史修订或多设备协作增加，再据载入耗时和数据库大小迁移分表、检索索引与按稿冲突检测。服务仅绑定回环地址，校验 Host 和浏览器写请求 Origin。账号和模型凭证由本地进程环境提供，前端只收到是否已配置的布尔值。应用不设后台采集定时器。

代码入口分为 `creator/server.py` 的请求与事务、`editor.py` 的编辑规则、`integrations.py` 的外部调用、`exports.py` 的导出和 `web/` 的界面。模型与外部内容均不能直接执行工具或发布。外部失败保留已有内容；真实计费请求不自动重试。

## 8. 测试与阶段验收

| 场景 | 验收观察 |
|---|---|
| 同一帖子导入两次、空链接后补节选 | 素材只保留一份。同事件多来源可分别溯源 |
| 缺本人观点、缺所选原文、模型产生无效引用 | 无法把此输入推进为合格的起草结果，返回可读原因 |
| 保存母稿、改稿、恢复、两个窗口同时保存 | 可以定位历史版本，过期写请求返回冲突 |
| 三种平台稿导出，改母稿后再导出 | 新版本文件格式正确；旧稿被拦截，核对后可以重新保存 |
| 模型服务失败、公众号正文不可取、X 缺凭证 | 明确提示，可继续手工编辑，已有稿件可恢复 |
| 规则提案、同篇与独立样本评测、撤回 | 同篇无法批准，独立评测保留依据，撤回后停止使用 |
| 真实试用 | 同一选题完成三稿，作者确认原话和关键事实，记录实际修改成本和最需要优化之处 |

仓库测试使用合成材料，HTTP 集成覆盖真实本机服务器和数据库，以及模拟模型协议、三种实际导出响应。真实账号联调、浏览器逐项点击、不同系统字体和作者署名质量应单列记录。通过协议测试不能证明生产模型质量或平台接收成功。

## 9. 交付顺序与重要节点

1. **首版工作台**：小窗口 X 采集、公众号按链接导入、素材与选题、母稿修订、三个平台导出、人工文风评测。
2. **真实首稿验收**：用作者选定的素材，接入其获准使用的模型和 X 账号。核对抓取成功率、实际调用费用、开稿到定稿耗时，以及各平台导入后的实际效果。
3. **热点雷达**：根据首轮采纳的选题扩充头部来源清单，验证游标与分页、独立出处、跨语言同事件、反例和相关度排序。计划采集频率由作者另行决定。
4. **草稿同步**：逐平台验证资格、权限和回执。账号可用时新增同步；保留文件导出路径。用户确认并亲自发表。
5. **可靠编排与改进**：依据原 Phase 0 的 Windows 会话恢复和双引擎试验作技术决定。随后评估真实文风改进、运营反馈及规则回滚。

源代码、测试与实现说明随 GitHub 分支交付。长期决策与里程碑沿用 Notion 项目页面，每个节点记录决定、验证范围、结果、证据链接与下一项依赖。
